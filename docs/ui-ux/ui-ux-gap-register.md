# EPAMS — UI/UX Gap Register (Stage U0)

**Project:** Employee Lifecycle and Service Management Platform (EPAMS)
**Phase:** P9.5 — Enterprise UI/UX Transformation
**Date:** 2026-11-18

---

| Finding ID | Current Behaviour | Usability / Quality Problem | Affected Users | Severity | Proposed Improvement | Acceptance Criteria | Related Component(s) |
| :--- | :--- | :--- | :--- | :---: | :--- | :--- | :--- |
| **UX-001** | No design system; ~100% inline hardcoded light hex colors across 25+ files; `<title>SpringApp</title>` in `index.html`. | Visual inconsistency, impossible theming, legacy boilerplate branding, high maintenance risk. | All users | **CRITICAL** | Create semantic CSS variable design system (`src/styles/design-system/`) with brand tokens, typography, spacing, shadows, and update `index.html` branding. | Zero hardcoded light-only page surfaces; consistent EPAMS enterprise identity across all routes. | `index.html`, `src/styles/design-system/*`, `App.css` |
| **UX-002** | Light mode only; no Dark or System theme support; no pre-paint theme script. | Eye strain in low-light environments; violates modern enterprise SaaS expectations (Fluent 2 / MD3). | All users | **CRITICAL** | Implement `PreferencesContext` (`light` / `dark` / `system`) + pre-paint inline `<script>` in `index.html` + dedicated dark tonal surface palette (`>= 4.5:1` contrast). | Theme switches cleanly across all screens, charts, badges, tables, and modals with zero FOUC and localStorage persistence. | `index.html`, `PreferencesContext.js`, `tokens.css` |
| **UX-003** | Fixed `230px` sidebar with no collapse mode and no mobile drawer; tables overflow page width. | Unusable on mobile (`390px`/`320px`) and cramped on tablet (`768px`) / laptop (`1366px`). | Mobile, tablet & laptop users | **CRITICAL** | Build collapsible desktop rail (`248px` / `72px` with tooltips), mobile slide-over drawer (`< 1024px`), hamburger toggle, and controlled table scroll wrappers. | Zero horizontal page scroll at `1440px`, `1366px`, `768px`, `390px`, `320px`; smooth drawer open/close + Escape dismiss. | `AppLayout.js`, `Sidebar.js`, `Navbar.js`, table views |
| **UX-004** | `LoginModal.js` embeds hardcoded demo credentials (`admin/admin123`, `john_doe/user123`), sets `outline: 'none'`, lacks `role="dialog"` / Escape key, and misreads `formatApiError` shape. | Security/hygiene violation (Rule 11), broken keyboard focus indicator (WCAG 2.2), confusing login error messages. | All unauthenticated users & keyboard users | **CRITICAL** | Remove hardcoded credentials from production login UI; restore `:focus-visible` rings; add `role="dialog"`, `aria-modal="true"`, Escape close, and read `err.detail`. | Clean enterprise sign-in modal; zero hardcoded credentials; full keyboard accessibility; accurate error banners. | `LoginModal.js` |
| **UX-005** | No Employee Profile (`/profile`) or Preferences (`/preferences`) screens despite backend `GET /api/profiles/me` existing. | Employees cannot view their org details, manager, contact info, or customize theme/density/accessibility. | All authenticated employees | **HIGH** | Implement `EmployeeProfile.js` backed by `GET /api/profiles/me` (read-only for employees with "Request Update" catalog link; edit link for Admin/HR) and `PreferencesPage.js` + top-bar Profile Menu. | Profile displays real backend data with generated avatar fallback; preferences persist theme, density, reduced motion, font scale locally with clear device-scope notice. | `EmployeeProfile.js`, `PreferencesPage.js`, `Navbar.js`, `App.js` |
| **UX-006** | Top bar lacks breadcrumbs, global navigation/service search, profile menu, and skip-to-content link. | Poor spatial orientation ("where am I / how do I go back"); slow multi-click navigation. | All users | **HIGH** | Add dynamic route Breadcrumbs, keyboard-accessible Quick Search (`Ctrl+K`) over supported routes/catalog/tickets, Profile Dropdown Menu, and Skip-to-Content link. | Users always see current location, can jump via Quick Search, and access Profile/Preferences/Theme/Help/Sign Out from top bar. | `Navbar.js`, `AppLayout.js`, `Breadcrumb.js`, `GlobalSearchModal.js` |
| **UX-007** | `Sidebar.js` and views rely on raw emojis (`📊`, `🎫`, `📥`) and lack accessible labels on icon buttons. | Unprofessional inconsistent cross-OS glyph rendering; poor screen-reader clarity. | All users & screen-reader users | **HIGH** | Create lightweight inline SVG icon set (`Icons.js`) with `aria-hidden="true"` and crisp `aria-label` attributes on interactive controls. | Consistent enterprise stroke iconography across sidebar, top bar, cards, and timelines (preserving existing test text matchers). | `components/common/Icons.js`, `Sidebar.js`, `Navbar.js` |
| **UX-008** | `TicketDetail.js` lacks visual 11-state lifecycle progress timeline and clear next-step guidance. | Employees cannot visually understand where their request sits in approval/fulfillment/dispute lifecycle. | Employees, Managers, Resolvers | **HIGH** | Add `StatusTimeline` component mapping all 11 backend states (`DRAFT` → `SUBMITTED` → approvals → `ASSIGNED` → `IN_PROGRESS`/`ON_HOLD` → `RESOLVED` → `CLOSED`, plus `REJECTED`/`CANCELLED` branches) and contextual next-step guidance. | All 11 states accurately visualized without inventing transitions; responsive horizontal/vertical layout. | `StatusTimeline.js`, `TicketDetail.js` |
| **UX-009** | `EmployeeDashboard.js` lacks recent notifications preview, quick profile/preferences shortcuts, and visual skeleton loading. | Employees miss unread alerts on login and see a generic spinner instead of structured layout skeletons. | All employees | **HIGH** | Upgrade `EmployeeDashboard.js` with personalized time-aware greeting, avatar identity bar, quick action bar, notifications preview widget (real `notificationService`), featured services, active tickets, and `LoadingSkeleton`. | Uses real backend APIs only; accurate backend `totalElements` count; skeleton loading states. | `EmployeeDashboard.js`, `LoadingSkeleton.js` |
| **UX-010** | `MyTickets.js` lacks priority filter, sorting, and card/table view switcher; `ServiceCatalog.js` lacks category chips. | Slow ticket triage and service discovery; poor mobile readability for wide ticket tables. | Employees | **MEDIUM** | Add priority filter, sort selector, Table/Card toggle on `MyTickets`; derive dynamic category filter pills from real catalog items on `ServiceCatalog`. | Zero fake categories; backend pagination preserved; clean card layout on mobile. | `MyTickets.js`, `ServiceCatalog.js` |
| **UX-011** | `DepartmentQueue.js` lacks search, priority filter, ticket age, and SLA health badge; `AuditLedger.js` lacks event search/filter. | Slower resolver triage and auditor log review. | Resolvers, Dept Heads, Auditors | **MEDIUM** | Add client search, priority filter, calculated ticket age, SLA countdown/breach indicator on `DepartmentQueue`; add action/actor search filter on `AuditLedger`. | Only operates on real department-scoped API data; clear SLA risk visibility. | `DepartmentQueue.js`, `AuditLedger.js` |
| **UX-012** | Modals (`CreateTicketModal`, `TicketDetail`, `ApprovalQueue`) lack `role="dialog"`, `aria-modal`, Escape dismiss, and confirmation polish; no `Toast` / `aria-live` status announcer. | Keyboard trap/escape failures (WCAG 2.2) and abrupt non-announced feedback. | Keyboard & screen-reader users | **HIGH** | Upgrade modal accessibility (`role="dialog"`, `aria-modal="true"`, Escape close, review summary in `CreateTicketModal`) and add accessible `ToastProvider` with `aria-live="polite"`. | All modals dismissible with `Escape`; dynamic notifications announced to assistive technology. | `ToastContext.js`, `CreateTicketModal.js`, `TicketDetail.js`, `ApprovalQueue.js` |
| **UX-013** | No `prefers-reduced-motion` handling or user reduced-motion setting; `LoadingSpinner` injects inline `<style>` and duplicates `EmptyState`. | Discomfort for motion-sensitive users (WCAG 2.3.3); minor CSS duplication. | Motion-sensitive users | **MEDIUM** | Move keyframes to design-system CSS, honor `@media (prefers-reduced-motion: reduce)` and `[data-reduced-motion="true"]`, remove duplicate `EmptyState` in `LoadingSpinner.js`. | Zero motion when reduced-motion is enabled; clean shared CSS animations. | `motion.css`, `LoadingSpinner.js`, `PreferencesContext.js` |
| **UX-014** | `AnalyticsDashboard.js` uses hardcoded light colors and SVG charts lack screen-reader summaries; Phase 1 Admin screens clash with shell. | Unreadable dark mode in analytics/admin; inaccessible charts for screen readers. | Managers, Auditors, Admins | **MEDIUM** | Migrate `AnalyticsDashboard.js` and Phase 1 `App.css` selectors (`table`, `.admin-form`, `.card`) to semantic design-system CSS tokens; add `role="img"` + `aria-label` + `<figcaption>` summaries on SVG charts. | Charts and admin tables adapt seamlessly to Light and Dark themes with accessible text alternatives. | `AnalyticsDashboard.js`, `App.css`, `Dashboard.css` |
